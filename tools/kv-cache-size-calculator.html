Where the formula comes from

During self-attention, every layer stores a key tensor and a value tensor for each token in the context. With grouped-query attention, several query heads share one KV head, so the cache holds num_key_value_heads × head_dim numbers per tensor per layer per token. In FP16 each number is 2 bytes, and there are two tensors, so bytes per token = 2 × num_hidden_layers × num_key_value_heads × head_dim × bytes per element. Worked check from the official Qwen3-8B config (36 layers, 8 KV heads, head_dim 128, BF16): 2 × 36 × 8 × 128 × 2 = 147,456 bytes per token, which is 4.5 GiB at 32,768 tokens.

Sliding-window models can cap the cache

Two of the presets, Mistral-7B-v0.1 and Phi-3-mini-4k-instruct, declare an active sliding window in their config, which can cap the cache. The Qwen2.5 configs list sliding_window 131072, but they set use_sliding_window to false. The Hugging Face transformers documentation says: "Note that for models using sliding window attention (Mistral, Gemma2,…) or chunked attention (Llama4), the cache will stop growing when the layers using these types of attention have reached their maximum size (the sliding window or chunk size)." Mistral-7B-v0.1 declares "sliding_window": 4096 and Phi-3-mini-4k-instruct declares "sliding_window": 2047. At context lengths above the window, the cache of the sliding-window layers can stop growing at the window size, so the result above can be an upper bound for these two models.

What the result does not include

The result is the KV cache only. Model weights, activations, CUDA context and framework overhead are extra. How much extra depends on the runtime and settings, so this page does not apply a fixed overhead percentage.

Why GQA matters so much

Qwen2.5-72B-Instruct declares 64 attention heads but only 8 KV heads. If the same model used classic multi-head attention, it would store 64 KV heads per layer instead of 8, eight times the cache. Phi-3-mini-4k-instruct uses full multi-head attention (32 KV heads at head_dim 96), so its 393,216 bytes per token exceed the 327,680 bytes per token of Qwen2.5-72B-Instruct.
